How it works

One machine runs the pool. Everyone else brings theirs. Work goes to whichever machine is free, and each job gets a fresh VM or sandbox that is thrown away after.

  1. Step 1

    Lay out the blanket

    On one machine, start a pool for your team and make invite codes. The first time, it gives you a Tailscale login link so your machines can find each other.

    $ potluck create team
$ potluck invite sam --host   # invite code for Sam

  2. Step 2

    Friends bring their machines

    On each machine you want to lend, check what it can safely run, then lend it with the code. If a check fails, the machine doesn't join and the code stays unspent.

    $ potluck doctor
$ potluck host '<code>'

  3. Step 3

    Leo comes back from lunch

    On a Mac, the moment its owner types or moves the mouse, its VMs end and it takes no new work. A Linux box doesn't notice its owner yet: it can be limited to set hours in its driver's settings.

    $ potluck host stop   # stop lending this machine

What you can do with it

Coding agents

Give your agent a computer of its own

Your agent's commands run in a throwaway sandbox on a pool machine, not on your laptop.

$ potluck sandbox create   # prints its id
$ potluck sandbox exec <id> -- make test
$ potluck sandbox rm <id>

Or hand it the sandbox tools over MCP:

{"mcpServers":{"potluck":{"command":"potluck","args":["mcp"]}}}

Using Claude Code's self-hosted runner? Run it in fresh sandboxes:

$ potluck agent-runner claude --secret-file <key-file>

House rules

Read these before you lend a machine. The full list is on GitHub.

  1. Work stays in a box

    Every job runs in a throwaway VM or sandboxed container, not directly on your system, and is deleted after.

  2. Pool with people you trust

    The machine that runs a job can read everything in it, secrets included. For now, so can the machine that runs the pool.

  3. Trusted or public

    You mark each machine trusted or public. Jobs that need your keys and tokens only go to trusted ones.

  4. Macs: lend, don't sell

    Apple's licence forbids selling Mac time. Our reading: lending a macOS VM to your team or friends is fine, and selling it to the public is not. Read the licence yourself. Linux VMs on a Mac are not affected.
