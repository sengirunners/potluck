The plan, in four paragraphs

  1. Set up a pool. Install Potluck on one machine and make a pool for your team. No account and no card.
  2. Add machines. Each person adds a Mac or Linux box. Potluck checks it first and says what it can safely run.
  3. Send it work. Point a GitHub Actions job or a coding agent at the pool. Each one gets a fresh VM or sandbox, thrown away after.
  4. Get your machine back. On a Mac, when you sit down, its VMs end and it takes no new work. On Linux, the same happens at hours you set.

Before you add a machine

The machine that runs a job can read everything in it, secrets included. Until commands are sealed to each machine's key, so can the machine that runs your pool's hub. Pool only with people you would trust with that.

Commands are not sealed yet.

Where the work runs
Work will run in a throwaway VM or sandboxed container, not directly on your system.
Trusted and public machines
Each machine will be marked trusted or public. Jobs that need your keys and tokens run only on trusted ones. Public machines get only plain sandboxes.
Free, at your own risk
Running it on your own machines will be free, with no account. Use it at your own risk; there are no promises.

A note on Macs

Apple's licence limits macOS VMs. Lending a macOS guest to your team or to friends you invite is fine; selling Mac time to the public is not.

Linux guests on a Mac are not affected.

This is not legal advice.
